# SECURITY.md
## VARUNA GRID v2 — security model

This system produces evidence that could contribute to a MARPOL enforcement action against
a named vessel. The security requirements follow from that, not from generic web-app
practice: the threat that matters most is not data theft but **a manipulated or
mis-attributed accusation**.

---

## 1. Threat model

| Adversary | Goal | Mitigation |
|---|---|---|
| Polluting operator | Avoid attribution | AIS spoofing detection; latent-source hypothesis; CHHAYA radar cross-check |
| Malicious third party | Frame an innocent vessel | Data Guard manipulation detection; trust quarantine; human sign-off before any name is acted on |
| Compromised data source | Corrupt inference at scale | Bounded Evidence Influence; cross-source consistency; source dependency registry |
| Insider | Alter a case or its evidence | Append-only PRAMAN; content hashing; RBAC; full audit trail |
| Opportunistic attacker | Data theft / disruption | JWT+RBAC, TLS, dependency scanning, container hardening |

**The system never names a vessel autonomously.** Every operational action crosses a human
authorization gate. That is a security control as much as an ethical one — it means no
single compromised component can produce an accusation.

---

## 2. Authentication and authorization

- **JWT** access tokens, short TTL, refresh rotation.
- **Argon2id** password hashing (`argon2-cffi`).
- **RBAC**:

| Role | Can |
|---|---|
| `viewer` | Read cases and analytics |
| `analyst` | Run pipelines, annotate, mark inconclusive |
| `officer` | **Authorize missions** (`human_approved_by`), override recommendations |
| `admin` | Manage users, promote model versions |

Enforced at the route layer and re-checked in `varuna_missions` — a direct call into the
mission FSM without an approving officer raises regardless of how it was reached.

---

## 3. Evidence integrity

| Control | Implementation |
|---|---|
| Raw immutability | `data/raw/` and PRAMAN store are append-only; overwrites rejected (threat G-02) |
| Content hashing | `EvidenceEnvelope.with_content_hash()` — sha256, order-independent (contract-tested) |
| Deterministic manifests | Sorted keys, fixed separators — same case ⇒ byte-identical manifest (threat G-03) |
| Chain of custody | `parent_artifact_ids` + `provenance.raw_artifact_refs` on every artifact |
| Human/AI separation | `recommended_by_system` and `human_approved_by` are distinct fields, never merged (threat O-05) |
| Model attribution | `model_version` stamped on every inference output (threat G-08) |

A case file that cannot be regenerated byte-for-byte from its raw inputs is not evidence.

---

## 4. Input validation

Every external byte passes Data Guard before reaching inference. Data Guard **fails
closed**: an unknown or unevaluable check yields `DEGRADED`, never `TRUSTED`.

Suspicious data is **down-weighted, never silently corrected** (ADR-0003). Quarantined
data is retained in full — it may itself be evidence of manipulation.

---

## 5. Application security

- Pydantic v2 validation on every boundary; `extra="forbid"` on contract models.
- SQLAlchemy parameterised queries only — no string-built SQL.
- CORS restricted to known origins in production.
- Nginx sets HSTS, CSP, `X-Content-Type-Options`, `X-Frame-Options`.
- Rate limiting on auth and pipeline-trigger endpoints.
- Uploads: type/size validated, stored in MinIO, never executed.
- Container runs as non-root (uid 10001).

---

## 6. Secrets

- Environment variables only. `.env` gitignored; `.env.example` committed with **no real values**.
- CI runs `bandit`, `pip-audit`, Trivy, and a regex secret scan that **fails the build**.
- Rotation: any credential exposed in a commit is rotated immediately, not just removed —
  git history preserves it.

---

## 7. LLM boundary

If a report-drafting LLM is used, it may **only** consume structured pipeline outputs and
inject numbers verbatim.

It may **never** modify: Φ · posteriors · trust states · evidence · asset assignment ·
alert severity · any enforcement decision.

**Every number in a generated report must be traceable to a structured field.** A model
that can invent a probability in a document that may reach an enforcement officer is an
unacceptable risk (threat G-09).

---

## 8. Dependency and supply chain

- `pip-audit` on every CI run; Trivy on every image build.
- Versions pinned in `pyproject.toml`.
- OpenDrift is GPLv2 and runs as a **separate process** — the boundary must not be blurred
  by linking it into a shared library.
- New dependencies require justification in the PR; major additions require an ADR.

---

## 9. Privacy

AIS is public safety-of-navigation data, but a *vessel* is often identifiable with an
*operator*. Accordingly:

- Retain only what the enforcement purpose requires.
- Never publish a suspect list outside the authorized recipient chain.
- A posterior is a lead, not a finding of guilt — the UI must never present it as one.
- Case data access is role-gated and audited.

---

## 10. Reporting

Security issues in this repository: raise privately with the team lead. Do not open a
public issue.

For a deployed instance: follow the operator's disclosure policy; do not test against
production data without written authorization.
